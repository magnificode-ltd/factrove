# Post-MVP 14 — Password-protected links

## Goal

Let the owner put an optional password on a public share link. A visitor with the link sees a password page and gets no artifact content until the password checks out. This builds on [task 15](15-shareable-links.md) and keeps all of its guarantees: links are `{PUBLIC_BASE_URL}/share/{id}/{token}`, tokens are AES-256-GCM ciphertext bound to the artifact id and looked up by SHA-256 hash, rotating the key revokes links, public loads omit credentials and are rate limited, and every inactive link is the same 404.

Read [the MVP end state](../../docs/MVP_END_STATE.md), [the project README](../../README.md), and [the shared contract](../mvp_contract.md). **Status: implemented in this change.**

## Owns

The `share_password_hash` column and its check, the owner password routes, the public unlock route, grants and content tickets, the password attempt limiter, the CLI password flags, the web password controls, and the visitor password page. No new environment variable. The grant key comes from the share-token key input.

## Behavior

- `POST /api/v1/artifacts/{id}/share` accepts no body or JSON `{ password }`. With a password it hashes first, then writes the share token and hash together when the artifact is unshared, or replaces the password on the current share. A hashing or write failure cannot leave a newly created unprotected link. Without a password it keeps the current password. `DELETE /share/password` removes the password and keeps the link. `DELETE /share` revokes the link and clears the password. Only the creator manages either. A non-JSON body is `400`. Passwords are 10 to 128 characters, not a common password from the bundled list, and normalised to NFC before hashing.
- Passwords are hashed with Argon2id from `node:crypto` (memory 19456 KiB, 2 passes, parallelism 1, 16-byte salt, 32-byte tag), stored as a PHC string. The plaintext is never stored or logged. Verification bounds the stored parameters, recomputes the tag, and compares with `timingSafeEqual`. Node 24.7 is the first release with `crypto.argon2`, so the engine floor is `>=24.7.0`. The API checks `typeof crypto.argon2 === "function"` at boot and exits with a readable message when it is missing.
- The share state, owner DTOs, and public detail include `passwordProtected`. The hash is never returned.
- Public detail on a protected link without a valid grant is `401 PASSWORD_REQUIRED`. Invalid, unshared, and revoked links stay `404 ARTIFACT_NOT_FOUND`, so the password page only appears for a live link.
- `POST /api/v1/public/artifacts/{id}/{token}/unlock` takes JSON `{ password }`. A missing or non-JSON body is `400` before any bucket is charged. Client and share slots are reserved before Argon2, including a correct password. The client bucket is 10 per 10 minutes (keyed like the view limit, IPv6 by /64). The share bucket is 30 per 10 minutes, keyed by the current share token hash. Both are separate from the view limiter. An exhausted or cooling share is `429 RATE_LIMITED` with no hash verification. A match refunds the client slot and keeps the share charge. Failed verifications start a per-share exponential cooldown. The owner recovers by sharing again, which mints a new token hash and a fresh budget. Concurrent Argon2 verifications on one process are capped; a saturated gate is `503 UNLOCK_UNAVAILABLE` and refunds both slots. A wrong password is `401 PASSWORD_INCORRECT`. A link without a password returns `{ grant: null }`.
- A correct password returns `{ grant: { token, expiresAt } }`. The grant is `g1.{exp}.{mac}`, valid for 15 minutes with 60 seconds of clock skew. The HMAC-SHA256 covers the artifact id, the share token hash, a SHA-256 fingerprint of the stored password hash, and the expiry. Its key is HKDF over `SHARE_TOKEN_KEY`, or `BETTER_AUTH_SECRET` when that is unset. A new password, including setting the same one again, has a new salt and fingerprint. Removing the password, revoking, or re-sharing changes the scope, and rotating the key changes the key. Existing grants stop working in all of these cases.
- Grant transport: the browser stores the grant in `sessionStorage` on the web origin, keyed by artifact id and bound to the token, and sends it in the `X-Factrove-Share-Grant` header on the credentials-omitted detail request. It is not a cookie, so it cannot ride along with other requests, and it is not in a URL, so it does not reach history, logs, or referrers. A new tab asks for the password again.
- The iframe cannot send headers. A granted detail therefore returns `contentUrl` with `?ticket=t1.{exp}.{nonce}.{mac}`, scoped like the grant, valid for 60 seconds, and redeemed at most 3 times per API process (preflight, a development double render, the frame load). N processes honor up to 3N uses in that window. Reverse proxies should not log `?ticket=`. The sandboxed document can read that ticket from its own URL, but the ticket expires within a minute and opens only the content that document already has. The document runs on the API origin without `allow-same-origin`, so it cannot read the parent's storage or the grant.
- Public CORS allows `POST, OPTIONS` on the unlock path and `GET, HEAD, OPTIONS` elsewhere, with credentials omitted and the grant header allowed.
- CLI: `share <id>` prints the URL and whether the link is password protected. A protected link also says to share again if visitors are locked out. `--password` prompts twice on a terminal without echoing. `--password-stdin` reads stdin and removes one trailing newline. `--remove-password` removes it, or says when there is no share or no password. A value given as an argument, such as `--password=secret`, is rejected. The password flags conflict with each other and with `--revoke`. No output includes the password.
- Web: the Public link panel shows the password state, with Add, Change, and Remove password. The viewer panel stays closed until the owner opens Sharing. The input has a show and hide toggle and validates 10 to 128 characters against the common-password list. A protected link tells the owner to stop sharing and share again if visitors are locked out. The visitor page shows the factrove wordmark and a lock card. A wrong password shakes the form, sets `aria-invalid`, and shows an alert. A correct one lifts the shackle and reveals the artifact. Motion is skipped under `prefers-reduced-motion`. An expired or invalidated grant returns the visitor to the form with a note.

## Verification

Unit tests cover the KDF (PHC format, salts, NFC, wrong passwords, tampered and out-of-bounds hashes), both throttle buckets, share backoff, the Argon2 gate, grant scope (artifact, token, password fingerprint, key, expiry, tampering), tickets, and the redemption ledger. HTTP tests cover protect and unlock, invalidation by change, removal, revoke, and key rotation, throttling, a non-JSON body that does not spend a bucket, a 31st attempt that is 429 even with the correct password, a re-share that resets the share bucket, 65 parallel unlocks from one IP, rotated IPs against one share, owner validation, CORS, and 404 versus 401 behavior. CLI tests cover stdin, the TTY requirement, inline-value rejection, conflicts, removal, and the unprotected and missing-password wording. Web tests cover the password page versus the 404 notice, the wrong-password state, grant storage and reuse, throttling, the owner controls, and a viewer panel that starts closed. `pnpm e2e` sets a password through the CLI, checks the stored Argon2id hash, opens the link without a cookie, enters a wrong password and then the right one, checks that the grant is absent from the iframe URL and unreadable from the frame, exhausts a ticket, changes the password in the web UI, checks that the old grant fails, removes the password, re-protects the link, and revokes it to a 404.

## Exclusions

No per-recipient passwords, no expiring links, no password recovery or hint, no lockout notification, and no shared throttle across API processes. The object key stays `{artifactId}.html`.
