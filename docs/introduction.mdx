Factrove stores HTML artifacts. People and agents upload files, the web app lists them, and a viewer opens the stored HTML. You can run that server yourself, or use Factrove Cloud, the hosted service. The web app, the HTTP API, and the CLI are the same product on both. The setup steps differ.

Self-host when you want the data on infrastructure you operate, or when you are changing this repository. The [self-host quickstart](/self-host/quickstart) installs the CLI, starts the server, creates the first user and an API key, and saves a CLI profile for your API origin.

Factrove Cloud when you want an account on the hosted service and do not want to run the server. The [Factrove Cloud quickstart](/cloud/quickstart) signs you up, creates an API key, installs the same CLI, and saves a profile for the hosted API.

Use a separate CLI profile for each. One `factrove configure` writes one profile, and a later configure of that same profile replaces its API origin.

## What you get

- A **web app** for sign-in, the library, and the viewer
- An **HTTP API** for artifacts, public shares, and API keys
- A **CLI** that uploads files, prints content, and manages share links

The published npm package is `factrove`.

```bash
npm i -g factrove
```

`npx factrove` runs it without a global install. A global install also puts `ftrv` on your PATH. `ftrv` is a bin alias of the `factrove` package, and it runs the same program. The package name you install, and the name you pass to `npx`, is `factrove`.

With no profile and no API URL, the CLI calls `https://api.factrove.app`. That origin is Factrove Cloud. A server you run needs its own API origin on the profile.

## Links use a base URL

Viewer and share URLs are a configured origin plus the artifact path. On a server you run, the API reads `PUBLIC_BASE_URL`, and a from-source process falls back to `WEB_ORIGIN` when that is unset. Setting the variable does not start a server. On Factrove Cloud, the hosted service sets that origin. This repository does not record the hosted web origin.

A server on your machine:

```text
http://localhost:3000/artifacts/{id}
http://localhost:3000/share/{id}/{token}
```

A self-hosted origin you choose:

```text
https://library.example.com/artifacts/{id}
https://library.example.com/share/{id}/{token}
```
